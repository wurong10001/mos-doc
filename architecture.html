架构设计

四层怎么分的

体验层 desktop.html / mobile.html
接入层 Cloudflare Worker
执行层 NativeActivity + C++
应用层 wasm3 + Wasm 模块

上面两层在 Web 侧，一次 HTTP 请求就走完了；下面两层在 Android 侧，跟网络没关系。 两边目前没有通信，各跑各的，这是眼下最大的结构缺口。

Web 入口

Worker 只做一件事：看到根路径，读 UA，把请求改写到对应页面，再把请求转给静态资源。 

if (url.pathname === '/') {
  const isTouchDevice = /android|iphone|ipad|mobile/i.test(userAgent);
  url.pathname = isTouchDevice ? '/mobile.html' : '/desktop.html';
}

没有后端，没有数据库，改界面就是改 public 目录下的 HTML 和 CSS。

Android 宿主

主循环在 main.cpp，引擎调度在 engine.cpp，Wasm 的加载和调用在 wasm_runner.cpp。 三者通过 app/src/main/cpp/CMakeLists.txt 一起编成 native library。

解释器选 wasm3 而不是 Wasmtime，原因是它体积小、依赖少，塞进 APK 不占地方， 代价是执行速度比 JIT 方案慢一截。

几个还没定的问题

  • Wasm 模块怎么调用系统能力，还没有 import 约定，现在只能自己跑自己
  • Web 端和 Android 端各有一套界面代码，视觉靠人工对齐，没有共享的部分
  • 应用从哪来、怎么装、版本怎么管，都还没开始设计
  • Native 层的日志和崩溃收集只在 Android 侧有，Web 侧什么都没有
