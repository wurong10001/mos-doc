第 05 节

动手跑起来

Web 端和 Android 端是两条独立的线，可以先挑一条跑通。 Web 端几分钟就能看到界面，Android 端麻烦一些，有个坑要提前知道。

需要准备什么

端 要装的东西 备注
Web Node.js、Wrangler 要部署到线上才需要 Cloudflare 账号，本地跑不用
Android Android Studio、Gradle、CMake 编译目标 30；只有重新编 .so 时才需要 NDK
教程站 浏览器 改完推 main，GitHub Pages 自己更新

Web 端

  1. 装依赖并启动本地服务：

    cd MOS
npm install
npm run dev

  2. 打开 Wrangler 给出的本地地址。正常情况会看到桌面版界面 —— 因为你的浏览器 UA 不含移动设备标识。

  3. 验证分流规则有没有生效：直接访问 /desktop.html 和 /mobile.html， 两个页面应该长得不一样。也可以在开发者工具里切到移动设备模拟，再访问根路径看它跳到哪边。

  4. 改一下 public/assets/system.css 里的颜色，刷新页面，改动立刻可见。 这能确认你没有构建步骤要等。

Android 端

  1. 用 Gradle 编出调试包：

    cd mos-android
./gradlew assembleDebug

  2. 装到设备或模拟器上打开。正常情况会启动 NativeActivity， C++ 主循环跑起来，sample.wasm 被加载执行。

  3. 用 adb logcat 看日志，确认 Wasm 模块确实跑过了。 这是目前唯一的验证手段。

改 C++ 之后必看

原生库不走 NDK 现场编译，是预编译好放进 jniLibs 的。 所以你改了 main.cpp、engine.cpp 或 wasm_runner.cpp 之后， 必须重新编译出 .so 并拷进 app/src/main/jniLibs， 然后再跑一次 ./gradlew assembleDebug。

只跑 gradlew，APK 里装的还是旧的 .so，改的代码不会体现。这一步最容易白折腾半天。

教程站自己

改 HTML 推到 main 就行。没有构建流程，Pages 会在推送后自动重新部署， 通常一两分钟内生效。想本地预览，随便起个静态服务器即可： 

python3 -m http.server 8000

改代码前先记住

  • Web 端没有构建步骤，HTML 就是最终产物
  • Android 端改 C++ 要手动重编 .so
  • sample.wasm 是唯一能跑的模块，加新模块先照着它的调用方式写
  • Wasm 和原生层之间没有接口约定，改这块之前建议先把约定写进文档

这一节要点

  • Web 端：npm run dev，用两个 HTML 路径验证分流是否生效
  • Android 端：./gradlew assembleDebug，用 logcat 验证 Wasm 是否执行
  • 改 C++ 后必须重编 .so，否则改动不进 APK
  • 教程站改完推 main 即可，无构建流程
