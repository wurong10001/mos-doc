第 06 节

继续深入

读完前面五节，你应该能说清这套系统是怎么拼起来的了。 这一节给三个可以直接动手的练习，再讲讲项目接下来要做什么、不做什么。

三个练习

按难度排，第一个几分钟就能做完，第三个要动 C++。

练习一 · 给分流规则加个分支

现在 UA 判断只有两种结果：触屏和桌面。平板会被判成触屏，拿到手机那套布局。 试着在 src/index.js 里加一个平板分支，匹配 tablet 或 ipad， 指向一个新的 tablet.html。

做完用开发者工具改 UA 验证。这个练习能让你把接入层完全摸清楚，因为它就只有这么点逻辑。

练习二 · 给 Worker 加一个新路径

目前只处理根路径。试着让 /about 返回一个简单页面， 注意别让它被后面的 env.ASSETS.fetch() 接管成 404。

做完你会理解「Worker 挡在静态资源前面」到底是什么意思 —— 哪些请求被拦下自己处理， 哪些转手给文件。

练习三 · 让 Wasm 模块拿到一个系统能力

这是 03 节说的那个缺口，也是最有价值的一个练习。目标：让 sample.wasm 能打印一行日志到 logcat。

  1. 在 Wasm 模块里声明一个导入函数，比如 mos_log，接受一个指针和长度。

  2. 在 wasm_runner.cpp 里用 wasm3 的 API 把这个函数链接到模块上。

  3. C++ 侧收到调用后，用 Android 的日志接口打出去。

  4. 重新编译 .so 拷进 jniLibs，再跑一次 ./gradlew assembleDebug。

做完这一步的意义

这就相当于定下了 Wasm 和系统之间的第一条接口。后面文件、计时、绘制这些能力， 都可以照这个模式加。项目里所有关于「应用」的设想都卡在这里，打通一条就通了。

项目接下来做什么

按依赖顺序排，前面没做完，后面基本没法开始：

定下 Wasm 和原生层的接口

就是练习三。先定一组 import 函数（日志、计时、读资源），在 wasm_runner.cpp 里实现。最优先，卡着后面所有应用开发。

让桌面图标点开后有东西

Dock 上的图标现在是摆设。最小改动是让点击打开一个窗口容器，容器里加载 Wasm 模块。依赖上一条。

应用包格式

一个应用包含什么、元信息怎么描述、版本怎么标。定下来之后 mos-repo 才有东西可放，也才能谈安装和更新。

窗口管理

Android 侧没有窗口概念，多开应用会互相覆盖。需要一套简单的窗口栈，处理切换、关闭和焦点。

日志和崩溃收集

Native 层的崩溃堆栈没有符号化，基本没法读。先把这个做起来，再做性能优化才有依据。

两边界面共用一套

Web 和 Android 各写一份，视觉靠人工对齐。长期需要抽一层共用描述，短期只能靠文档约束。

暂时不做的

  • 多用户、权限体系
  • 应用商店和在线分发
  • 把 wasm3 换成带 JIT 的运行时 —— 先跑通再谈性能

这一节要点

  • 练习一和二只需要改 Web 端，几分钟能做完，适合先建立手感
  • 练习三打通 Wasm 和原生层，是项目当前最关键的缺口
  • 后续工作按依赖排序，接口约定是所有应用开发的前置
  • 多用户、分发、换运行时都在「暂时不做」的清单里
