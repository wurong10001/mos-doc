第 04 节

代码在哪

四个仓库，没有互相依赖，谁也不 import 谁。 它们只是概念上分层：入口在 MOS，运行时在 mos-android，以后的应用包放 mos-repo，教程写在这里。

MOS · Web 入口

目前唯一能公开访问的部分。Worker 加两个静态页面，代码量很小，适合第一个读。

  • src/index.js — 全部服务端逻辑，就一个 UA 判断
  • public/desktop.html — 桌面端界面
  • public/mobile.html — 触屏端界面
  • public/assets/system.css — 两边共用样式

改动影响面很小：改 index.js 影响分流规则，改两个 HTML 和 CSS 只影响界面。没有构建步骤，改完刷新即可。

mos-android · 原生宿主

标准 Gradle 工程，C++ 部分用 CMake 编。四个文件值得先看：

  • app/src/main/cpp/main.cpp — 主循环，从事件队列取事件
  • app/src/main/cpp/engine.cpp — 调度，把事件分给该处理的地方
  • app/src/main/cpp/wasm_runner.cpp — 加载 .wasm、调用其中的函数
  • app/src/main/assets/sample.wasm — 唯一能跑的示例模块
改这里之前注意

原生库是预编译好放进 jniLibs 的，不在本地走 NDK 编译。 改了 C++ 之后要重新编出 .so 再拷过去，只跑 gradlew 不会生效。 这么做的目的是为了在 Termux 这类没有完整 NDK 的环境里也能构建 APK。

mos-repo · 软件源

打算放应用包的地方。现在除了一个写着「MOS 系统软件源」的说明文件，里面什么都没有。

它空着是有原因的：应用包里该有什么、元信息怎么描述、版本怎么标，这些都还没定。 格式定下来之前，这个仓库没有东西可放。

mos-doc · 这个教程

你正在看的站点。纯静态，几个 HTML 加一个 assets/style.css，托管在 GitHub Pages。

改动流程：改 HTML，推到 main 分支，Pages 自动重新部署。

对照表

仓库 主要语言 该先看的文件
MOS JavaScript / HTML / CSS src/index.js
mos-android C++ / CMake app/src/main/cpp/wasm_runner.cpp
mos-repo — README
mos-doc HTML / CSS index.html

这一节要点

  • 四个仓库互不依赖，只是概念上分层
  • 想最快看懂全貌，先读 MOS 的 src/index.js，一共没几行
  • mos-android 的 C++ 改动需要手动重编 .so，这是最容易踩的坑
  • mos-repo 现在是空的，等应用包格式定下来才有内容
