第 06 节

写第一个应用

这一节带你从零写出一个能被 MOS 加载的应用：搭建环境、写模块、编译成 .wasm、在设备上跑起来看日志。目标是走通一整圈。

准备工具

需要三样东西，都是命令行工具：

  • 编译器：能把 C/C++ 编成 Wasm 的 clang，或者 Rust 的 wasm32 目标
  • 运行时：本机跑一个 Wasm 运行时，用来在电脑上先验证逻辑，不用每次都装到设备
  • MOS 本体：浏览器打开即可测 Web 端，Android 端需要有编译好的 APK

选语言

语言 适合 产物特点
C / C++ 已有原生代码要移植，或者对体积敏感 产物最小，需要手动管内存
Rust 新写的逻辑，希望有类型安全 产物略大，编译器能挡掉一大类错误

两种都行，MOS 不挑。下面的例子用 C，因为它最直白， 能看清导入导出是怎么写出来的。

写模块

按 05 节的约定，模块要导出四个函数，要用系统能力就导入对应的函数。 先看一个最小的骨架： 

// 导入：宿主提供
extern void mos_log(const char* ptr, int len);
extern long long mos_now_ms(void);

// 导出：宿主调用
__attribute__((export_name("mos_init")))
void mos_init(void) {
  const char msg[] = "hello mos";
  mos_log(msg, sizeof(msg) - 1);
}

__attribute__((export_name("mos_event")))
void mos_event(int type, int a, int b) { }

__attribute__((export_name("mos_frame")))
void mos_frame(void) { }

__attribute__((export_name("mos_stop")))
void mos_stop(void) { }

几个要点：

  • 导入函数只声明不实现，实现在宿主那边，加载时才接上
  • 导出函数要显式指定导出名，C 编译器默认会加下划线前缀
  • 字符串参数传的是指针加长度，不是 C 风格的字符串 —— Wasm 的内存是独立的一块，宿主不能直接读
  • 四个导出函数即使暂时用不到也要有，宿主加载时找不到会报错
关于内存

模块有自己独立的一块线性内存，宿主那边看到的就是一个字节数组。 所以传递字符串、结构体这类数据，都是「传地址 + 传长度」， 两边约定好布局。这是 Wasm 开发里最需要适应的地方。

编译

$ clang --target=wasm32 \
    -nostdlib -Wl,--no-entry \
    -Wl,--export=mos_init \
    -Wl,--export=mos_event \
    -Wl,--export=mos_frame \
    -Wl,--export=mos_stop \
    -Wl,--allow-undefined \
    -O2 -o app.wasm main.c

几个参数的含义：

  • --target=wasm32 — 输出 Wasm 而不是本地机器码
  • -nostdlib — 不带标准库，让产物尽量小。需要的话再单独链
  • --no-entry — 模块没有 main 函数，它是被调用的，不是自己跑的
  • --allow-undefined — 允许留着导入函数不解析，等宿主加载时填

编译完看一下产物大小，正常应该是几 KB 量级：

$ ls -lh app.wasm

先在本机验证

别急着装到设备上。先用一个 Wasm 运行时在本机跑一遍， 手动把 mos_log 接上去，看能不能输出那行 hello： 

$ wasm3 app.wasm
hello mos

这一步能挡掉大部分低级错误：导出名写错、导入没接上、编译参数漏了。 本机跑通了再去设备上，排查范围小很多。

放到 MOS 上跑

  1. 按 07 节的方式把模块和清单打成一个应用包。

  2. 通过软件源安装，或者用开发者方式直接推送到设备。

  3. 在桌面上点开应用图标。

  4. 看日志：Android 端用 adb logcat，Web 端在浏览器控制台。

如果那行 hello 出现在日志里，说明整条链路通了： 宿主加载了你的模块、注册了导入函数、调用了 mos_init。 接下来的事就是往 mos_frame 里填真正的绘制逻辑， 往 mos_event 里填交互处理。

调试建议

  • mos_log 是你最主要的调试手段，Wasm 里没法下断点，靠打日志定位
  • 导入函数没接上时，模块加载阶段就会失败，日志里会写清缺哪个
  • 内存越界在 Wasm 里会直接终止模块，通常表现为应用无响应退出
  • 逻辑先在本机跑通，再去设备上调界面，效率差很多

这一节要点

  • 工具三样：Wasm 编译器、本机运行时、MOS 本体
  • 模块导出四个函数，用系统能力就导入对应函数
  • 编译要点：--no-entry、--allow-undefined、显式导出名
  • 传数据是传地址加长度，模块内存对宿主就是一个字节数组
  • 先本机跑通再上设备，日志是主要调试手段
